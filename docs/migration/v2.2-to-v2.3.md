# Migrating CineWeave Studio V2.2 to V2.3

V2.3 is an additive upgrade. Existing 2.0 and 2.2 creative artifacts, V2.2
project manifests, artifact envelopes, approval records and board provenance
remain valid. Do not rewrite immutable artifacts merely to change a version
string.

## Plugin upgrade

Install the immutable V2.3 tag and start a new Codex task:

```bash
codex plugin marketplace add Wilder1222/cineweave-studio --ref v2.3.0
codex plugin add cineweave-studio@cineweave-studio
```

If the marketplace already exists, update it and then update the installed
plugin instead of adding a duplicate marketplace.

## Existing local projects

Opening a V2.2 project with `init` is non-destructive. The old `project.json`
remains unchanged while the runtime ensures the new `executions/` and
`idempotency/` directories exist. New artifacts use V2.3 envelopes; old and new
records may coexist because all dependencies use exact refs and hashes.

Run verification before and after the upgrade:

```bash
node packages/cineweave-runtime/bin/cineweave.mjs verify <project-directory>
```

## New execution records

V2.2 `CapabilityProfile` and `RenderPlan` records do not authorize execution.
To execute through V2.3, add:

1. an exact `AdapterDescriptor` matching a trusted registered implementation;
2. a stored `ExecutionRequest` binding exact adapter, capability, render-plan,
   prompt and input refs;
3. approval of that exact request when `executionMode` is `external`;
4. explicit caller enablement for external effects;
5. a runtime-authored `ExecutionReceipt` after execution.

Never migrate endpoint URLs, signed URLs, credential values or arbitrary module
paths into these contracts. Credential environment-variable *names* may be
declared by trusted adapter metadata; values stay outside artifacts and logs.

## Live evaluation

Committed replay grading is deterministic and part of the release gate:

```bash
node scripts/run-live-skill-evals.mjs --grade tests/fixtures/live-responses --summary-only
```

Real model calls are intentionally opt-in and require a model, a new local
output directory and explicit cost acknowledgement:

```bash
node scripts/run-live-skill-evals.mjs --run --acknowledge-model-costs \
  --model <model> --out-dir .cineweave-evals/v2.3-smoke
```

Live transcripts stay ignored and local. The committed dataset contains only
synthetic prompts; do not add user assets, secrets or private conversation text.

## Rollback

V2.3 does not mutate V2.2 artifacts or project manifests. Rolling back the
plugin therefore requires only reinstalling `v2.2.0`. A V2.2 runtime will ignore
new execution artifacts it does not consume, but it cannot execute or verify
V2.3 output receipts; keep a V2.3 verification report before rollback.
