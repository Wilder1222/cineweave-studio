# Migration from CineWeave Creative Skills v1.1 to CineWeave Studio v2

V2 removes the temporary V1 packaging shape and introduces a product-level
router, a versioned contract package and portable specialist bundles. It does
not silently change a character, scene, style, prompt or rights record.

## What changed

| V1.1 location or behavior | V2 replacement |
|---|---|
| root `schemas/`, `examples/`, `recipes/`, `contracts/` | `packages/cineweave-contracts/` |
| root `evals/` | `tests/fixtures/evals/` |
| Director `brief_compile` | `$cineweave` `creative_intake` |
| Director as general product entry | `$cineweave` router; Director remains independently usable for shots and prompts |
| implicit cross-skill context | `CreativeBrief` and `WorkflowPlan` with explicit artifact handoffs |
| plugin `cineweave-director@1.1.0` | product package `cineweave-studio@2.0.0` |

## Contract migration

The V2 migration command creates a new file. It never overwrites the source or
invents missing StyleCompile, CharacterBinding, SceneBinding, evidence, rights
or production data.

```bash
node scripts/migrate-v1.1-to-v2.mjs legacy.json \
  --out migrated-v2.json \
  --report migration-report.json \
  --schema packages/cineweave-contracts/schemas/character-appearance-state.schema.json
```

The result receives `contractVersion: "2.0.0"`. Review the report before
importing it as a new version.

## Workflow migration

For a previous natural-language Director request:

1. Use `$cineweave` when the request spans more than one domain.
2. Approve or edit the returned `CreativeBrief`.
3. Run the indicated specialist Skills directly or as composed steps.
4. Pass only exact approved artifacts to Director or Production.

For a bounded single-domain request, invoke the specialist directly. For
example, `$cineweave-director` still handles a one-off prompt without requiring
the router.

## Source compatibility

This repository is intentionally V2-first. It does not keep a runtime V1
compatibility layer or accept V1 contract versions in V2 schemas. The migration
tool is the explicit, non-destructive boundary between the two versions.
