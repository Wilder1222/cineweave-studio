# V2.4 reference assets and role binding decisions

## Outcome

V2.4 promotes reference handling from an informal list of uploaded images to a
standalone, composable evidence lifecycle:

```text
untrusted local bytes
        ↓ bounded ingest
ReferenceAsset (exact byte identity)
        ↓ visible or declared evidence
ReferenceObservation (one role + one selector)
        ↓ purpose-specific judgment
ReferenceReview
        ↓ conflict and rights resolution
ReferenceBindingSet (exact downstream targets)
```

This division prevents one image from silently becoming the authority for a
person's identity, costume, pose, palette, composition and camera treatment at
the same time. It also makes byte integrity, visual evidence, provenance trust
and legal permission independently visible.

## Standards and guidance considered

The implementation borrows concepts from standards without claiming conformance
where the runtime does not implement the complete standard.

- The [W3C Web Annotation Data Model](https://www.w3.org/TR/annotation-model/)
  separates a source/target from the body of an annotation and supports
  selectors for a segment of a resource. CineWeave similarly separates an
  exact `ReferenceAsset` from role-scoped `ReferenceObservation` records.
- [W3C Media Fragments URI 1.0](https://www.w3.org/TR/media-frags/) describes
  temporal and spatial fragments. CineWeave uses normalized rectangles and
  integer millisecond ranges internally, but does not claim that its selector
  JSON is a Media Fragments URI serialization.
- The [C2PA 2.4 specification](https://spec.c2pa.org/specifications/specifications/2.4/specs/C2PA_Specification.html)
  and its [security considerations](https://spec.c2pa.org/specifications/specifications/2.4/security/Security_Considerations.html)
  treat manifests, assertions, signing and trust as a provenance system with a
  threat model. CineWeave therefore records content-credential status and trust
  separately from SHA-256 byte identity. Core does not validate C2PA manifests,
  ship a trust list or claim C2PA certification.
- [IPTC Photo Metadata 2025.1](https://www.iptc.org/std/photometadata/specification/IPTC-PhotoMetadata-2025.1.html)
  demonstrates that image files can carry creator, rights, location and other
  embedded metadata. V2.4 preserves but does not inspect original metadata and
  requires a privacy review before external transfer.
- The [OWASP File Upload Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html)
  recommends defense in depth: allow-list extensions, distrust supplied media
  types, validate signatures, rename files, limit size, restrict storage and
  use scanning where appropriate. V2.4 implements a local bounded subset and
  states the missing layers explicitly.

## Contract ownership

`cineweave-reference` owns six routes:

| Route | Smallest owned result |
| --- | --- |
| `reference_ingest` | immutable `ReferenceAsset` envelope |
| `reference_verify` | mechanical exact-byte verification report |
| `reference_observe` | one atomic `ReferenceObservation` |
| `reference_review` | purpose-specific `ReferenceReview` |
| `reference_bind` | exact ordered `ReferenceBindingSet` |
| `reference_set` | explicit legacy V2.0 compatibility result |

It does not design characters, scenes or styles, direct shots, compile model
prompts, execute providers, scan malware or authorize legal use. Production
owns authoritative `LicenseProfile` records and execution gates; each creative
Skill owns the meaning of accepted evidence inside its domain.

All nine Skills remain directly callable. A user can ask only whether one image
is a suitable palette reference, or a WorkflowPlan can ingest once and route
separate identity, costume, geography and lighting observations to different
specialists.

## Exact-byte asset boundary

The local runtime accepts only these extension/media pairs:

| Extensions | Stored format |
| --- | --- |
| `.png` | PNG |
| `.jpg`, `.jpeg` | JPEG |
| `.webp` | WebP |
| `.mp4`, `.m4v` | allow-listed ISO-BMFF video brand |
| `.mov` | allow-listed QuickTime/ISO-BMFF video brand |
| `.webm` | EBML with WebM DocType |

The ingest path:

1. rejects links and non-regular files;
2. applies a 64 MiB default image limit or 512 MiB video ceiling;
3. compares the allow-listed input extension with a bounded signature/container
   probe, then records one canonical extension per detected format so aliases do
   not create competing payloads for the same byte identity;
4. checks PNG/JPEG/WebP dimensions, a 65,535 per-axis ceiling and a 100 million
   pixel ceiling without decoding pixels;
5. computes SHA-256 over the complete input;
6. copies through a private temporary file and stores bytes under
   `reference-blobs/sha256/<prefix>/<digest>.blob`;
7. writes a `ReferenceAsset` artifact without the source path or original
   filename; and
8. verifies the stored byte length, hash and non-executable mode.

Equal bytes from the same source class deduplicate to the same exact asset.
Equal bytes declared under a different source class may share one blob while
remaining separate semantic asset records. This preserves the distinction
between a user upload and a generated output without duplicating bytes.

The probe deliberately does not decode images or video. It therefore cannot
prove that every frame is well formed, that a media library can safely parse
the file or that the content is benign. It is an ingestion boundary, not a
malware scanner or content moderation system.

## Atomic observations

One `ReferenceObservation` has exactly one primary role and one selector:

- `full_asset`;
- `spatial_rect` with a normalized rectangle;
- `temporal_range` in milliseconds;
- `spatiotemporal_rect`; or
- `mask_asset` with an exact mask-asset ref.

The observation records:

- evidence basis (`visible`, `declared`, `inferred` or `unknown`) and
  confidence;
- what may be extracted and what must be ignored;
- allowed transforms and forbidden uses;
- independent authority for identity, appearance, performance, capture, style
  and environment; and
- exploration, production and redistribution rights gates.

`extract` and `ignore` must be disjoint. A static image cannot be authoritative
for camera motion or performance timing. Style evidence cannot overwrite
identity, and composition evidence cannot overwrite scene geography. If one
image contributes both identity and palette, it produces two observations,
each with its own authority and ignore rules.

Video ingestion currently proves only a bounded container signature. Temporal
observations should remain draft until a trusted media probe supplies and checks
duration. This limitation is explicit rather than filled with inferred values.

## Binding and rights boundary

`ReferenceBindingSet` lists exact observation refs for exact target contracts.
It records priority, required/optional state, resolution order, same-role and
overlapping-selector policy, and whether all rights profiles are resolved.

An active or locked binding set cannot contain unresolved observations. Unknown,
restricted or blocked rights may support private exploration under policy, but
cannot be promoted to production or redistribution. A verified gate requires an
exact `LicenseProfile` ref.

Ingestion never implies:

- copyright ownership;
- a license to generate, publish or redistribute;
- consent to reproduce a person's likeness;
- permission to train a model;
- a trustworthy creator identity; or
- permission to transfer bytes to an external provider.

These are separate declarations and approval decisions even when content
credentials are present and valid.

## Artifact graph and project bundles

Observations depend on exact asset refs, so ArtifactGraph can report missing,
hash-mismatched and superseded evidence rather than relying on an uploaded-file
label. Approval never transfers to a newer asset or observation version.

V2.4 ProjectBundle format 1.1 includes every referenced blob as an allow-listed,
hash-listed regular file. Import rejects links, traversal, duplicate/unexpected
entries, changed bytes and pre-existing target stores. The bundle policy states
whether reference media is present and never implies redistribution permission.
The parser retains support for V2.3.1 format 1.0 bundles without rewriting their
project manifest.

## Threat model and non-goals

| Threat or ambiguity | V2.4 response | Residual risk / non-goal |
| --- | --- | --- |
| extension spoofing | extension and bounded signature must agree | full decoder validity is not proven |
| oversized image header | byte, axis and pixel ceilings | decompression/runtime bugs are outside core |
| arbitrary ISO-BMFF or EBML | allow-listed video brand / WebM DocType | codecs, tracks and duration are not decoded |
| active file execution | generated names, blob extension, non-executable mode | downstream applications still need safe parsers |
| source-path disclosure | no path or original filename in the asset contract | original bytes may embed private metadata |
| silent reference contamination | one role/selector, extract/ignore, authority | model adapters may offer weaker controls and must disclose this |
| changed bytes | complete SHA-256 and exact ArtifactGraph refs | hash is not signer identity or authorship |
| public image mistaken for licensed image | rights stay unknown until exact profile/approval | legal review remains external |
| transfer container abuse | fixed paths, regular files, hash manifest, staged import | bundle sender is not authenticated |
| malware/content safety | status explicitly records `not_run` | scanning/classification require separate trusted tools |

## Highest-value follow-ups

1. Add an immutable derived-asset contract for thumbnails, proxies and
   metadata-stripped copies while preserving the original asset/ref lineage.
2. Add pluggable inspection reports for malware scanning, decoded technical
   metadata and Content Credentials; absence or stale inspection must remain
   visible and blocking under policy.
3. Add trusted video duration/frame-dimension probes before temporal selectors
   can become approved.
4. Add adapter conformance tests that show how provider-specific identity,
   style, pose, mask and negative-reference controls degrade from the semantic
   binding set.
5. Add rights-cleared multi-domain reference cases and regression fixtures for
   identity preservation, content leakage and role conflict resolution.
6. Consider perceptual duplicate detection only as advisory evidence. It must
   never replace exact byte identity and requires a separate privacy and false-
   match threat model.

The V2.4 invariant is therefore:

> Bind exact bytes, extract one declared role at a time, keep provenance and
> permission separate, and make every unresolved boundary visible before
> production use.
